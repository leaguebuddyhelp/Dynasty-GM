# CUS01 prospect cards

Run `/prospects` in Discord, choose a position, then choose a player. The browser is private to the operator. There are 96 published profiles: six QBs, seven HBs, seven WRs, seven TEs, four LTs, two LGs, two centers, two RGs, six RTs, eight LEDG, eight REDG, five DTs, four SAMs, five MIKEs, three WILLs, 11 CBs, four FSs and five SSs. Positions stay separate. Other positions remain available in the menu with an unpublished notice.

`/earlytop10` opens the separate preseason list in `bundled_data/madden/Madden - CUS01 - Early Top 10.json`, one ranked slot per page. Its scouting blurbs live in `early-top-10-bios.json` and use the early list's notes rather than the later board's reports or statistics. Empty ranks are marked unassigned; an entry without an authored blurb says its report is coming soon. Portraits are matched by name, position and school to the existing CUS01 prospects, not by rank. The new command must be registered with the production command deployment script before it appears in Discord.

Player measurements, school, class year, jersey and board rank come from `bundled_data/madden/Madden - CUS01.json`. Archetype is only a writing guide and is omitted from cards and menus, along with overall ratings and development traits. The source school spellings `Minneosta`, `Wiconsin` and `Western Kentucy` display as Minnesota, Wisconsin and Western Kentucky. This command does not change `/bigboard` or its file selection.

`profiles.json` holds authored scouting profiles, simulated college statistics and portrait filenames, keyed by source record ID. The source record's `bio` field guides each 35–45-word scouting write-up and the simulated season where relevant. College statistics are labeled as simulated on cards; they are not EA imports, actual results or inputs to awards or progression. No injury histories were invented. Profiles must match the source name and have all seven appearance fields before publication. To add another position, complete its source appearance fields, add an editorial profile and save its portrait in `portraits/`.

Efficiency is calculated from the authored totals rather than entered separately: yards per route run is receiving yards divided by routes; rushing yards after contact per carry uses after-contact yards divided by carries; ANY/A is `(passing yards + 20 × TD − 45 × INT − sack yards) / (attempts + sacks)`. Catch rates and yards after catch per reception use their corresponding totals. TE and OL blocking profiles can include fictional run-block wins per assignment and pressures allowed per pass-block snap. OL pressure totals sum the authored sacks, hits and hurries, with penalties and offensive snaps shown separately. These fictional college metrics are descriptive scouting material, not measured Madden attributes or external analytics grades.

DL profiles show authored pressures per pass-rush snap, run stops per run-defense snap, tackles, tackles for loss, forced fumbles and missed tackles. Missed-tackle rate is misses divided by recorded tackles plus misses. Pressure totals sum distinct sack plays, hits and hurries; a shared sack can produce half a credited sack while still counting as one sack play. Credited sacks remain in half-point increments. Run-focused profiles are assessed with their run contribution rather than treated as unsuccessful solely for a lower sack total.

Linebacker and defensive-back profiles show fictional tackles, tackles for loss, sacks, forced fumbles, run stops per run-defense snap, coverage targets and completions allowed, pass breakups, interceptions and missed-tackle rate. These figures and scouting biographies are authored material for the cards, not imported statistics.

Portraits were generated with the built-in imagegen tool, using individual prompts recorded in `portrait-prompts.json`. Each is an independent fictional adult athlete, in the named school's branded jersey and colors. Background removal edits are recorded in `transparent-portrait-prompts.json`; cards use the resulting transparent PNG cutouts. Jaquon Hall's conflicting hair fields were resolved using the explicit `hair_color: black` value. Vague facial descriptions were interpreted naturally without inferring character or athletic ability from ethnicity or appearance.

HB, WR, TE, OL and DL portraits were generated directly with alpha transparency using the prompts in `hb-portrait-prompts.json`, `wr-portrait-prompts.json`, `te-portrait-prompts.json`, `ol-portrait-prompts.json` and `dl-portrait-prompts.json`. Colt Fisher's portrait follows the corrected white/fair skin, blue eyes and brown hair. Cards reuse supplied school emoji IDs where available; schools without a supplied emoji use a text label and school color.

Linebacker and defensive-back portraits were generated with alpha transparency using `lb-portrait-prompts.json` and `db-portrait-prompts.json`.

The assets are bundled with the bot and attached directly to Discord cards. There are no runtime AI requests or new API keys required. When deploying, register the `/prospects` command using the existing production command deployment script, then restart/deploy the updated bot.
